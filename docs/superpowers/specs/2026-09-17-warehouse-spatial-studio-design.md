# Warehouse Spatial Studio Prototype Design

## Purpose

Build a standalone approval project that reproduces the supplied warehouse Spatial Studio design without reusing the ERP project's current spatial implementation. The prototype must run on localhost, begin with an empty warehouse envelope, support a real parent-linked warehouse hierarchy, and provide synchronized 2D and 3D views. The ERP repository remains untouched until the user approves this prototype.

## Visual target

The card follows the supplied Building, Storage, Layout, and Review screenshots:

- compact white-and-blue enterprise UI with 1px neutral borders;
- a title/mode bar, context toolbar, three-column workspace, and bottom status bar;
- left configuration/library panel, central engineering grid, and right property inspector;
- persistent labels, dimension annotations, blue selection handles, grid snapping, validation badges, hierarchy breadcrumbs, and zoom controls;
- responsive behavior that preserves the center canvas while allowing the side panels to scroll.

The separate prototype does not reproduce the ERP Create Warehouse header. During later integration, the existing ERP header stays and this prototype replaces only the body.

## Technology

- React 19 + TypeScript + Vite for a component structure that can later transfer into the React ERP frontend.
- Zustand for a single normalized studio state and undo/redo snapshots.
- Konva/react-konva for 2D hit testing, drag/resize transforms, grid rendering, and pointer interaction.
- Three.js through React Three Fiber and Drei for synchronized 3D, OrbitControls, selection, and DOM-quality labels.
- Lucide React for the compact toolbar icon language.
- Vitest + Testing Library for state, hierarchy, geometry, and shell behavior tests.

## Workspace anatomy

1. `StudioHeader`: Spatial Studio title, active hierarchy breadcrumb, Template/Custom switch, 2D/3D switch, fullscreen action.
2. `ContextToolbar`: Select/Pan tools; context-aware Add actions; Snap, Grid, Dimensions, Labels, and Faces/Routes toggles; undo/redo.
3. `LibraryPanel`: Building, Storage, or Layout controls plus a hierarchy tab. Items can be clicked or dragged into the canvas.
4. `Canvas2D`: engineering grid, dimension rulers, object labels, selection transformer, containment feedback, zoom/pan, and fit.
5. `Scene3D`: extruded warehouse/hall/room/zones, aisles, racks, shelves, bins, shutters, synchronized selection, labels, orbit/pan/zoom, and fit.
6. `PropertiesPanel`: type-specific editable name, code, dimensions, position, rotation, lock, duplicate, delete, and parent path.
7. `StatusBar`: selection, validation summaries, hints, zoom percentage, Fit, and sample/reset actions.

## Domain model and hierarchy

Every node has `id`, `type`, `parentId`, `name`, `code`, `x`, `y`, `width`, `depth`, `height`, `rotation`, `locked`, and type-specific metadata. Coordinates are local to the parent.

Allowed parent relationships are strict:

```text
Warehouse
└── Hall | Room
    ├── Aisle
    │   └── Rack
    │       └── Shelf
    │           └── Bin
    ├── OpenStore | Operational Zone
    └── Gate | Shutter
```

The warehouse root always exists. The initial document contains only that empty envelope. Adding an object requires a valid active parent. Invalid drops show a visible rejection message and do not mutate state. Moving/resizing an object clamps it inside its parent. Codes are unique and generated by type (`HL01`, `AV01`, `RA01`, `SH01`, `BN01`, and so on).

## Interaction design

- Click a palette item to add it at the center of the active parent, or drag it over a valid parent on the 2D canvas.
- Click an object or tree row to select it; selection is shared between 2D, 3D, breadcrumb, hierarchy, and inspector.
- Drag selected objects; snapping rounds coordinates and dimensions to the configured grid.
- Resize through Konva Transformer handles. Warehouse and structural areas use four corner/edge handles; shutters remain edge-aligned.
- Double-click a container to make it the active editing scope.
- Undo/redo stores bounded document snapshots. UI-only state is not added to history.
- `Load sample` creates the screenshot-inspired arrangement for review. `Clear warehouse` returns to the empty envelope.
- 2D and 3D are alternate renderers of the same state; neither maintains private geometry.

## Measurement and labeling

- Model values use feet for the prototype and render with `ft` labels.
- The canvas scales world values to pixels and draws overall/selected width and depth dimensions.
- Every visible structural object shows its code; larger containers also show the display name and formatted size.
- 3D uses consistent world dimensions, CSS labels, and type-specific heights.

## Validation

The live validation layer reports:

- invalid parent relationships;
- objects outside parent bounds;
- sibling rectangle overlaps for halls/rooms, racks, and operational zones;
- missing required ancestors;
- duplicate codes;
- empty containers as recommendations rather than blocking errors.

## Scope boundaries

- No ERP source files, APIs, authentication, persistence schema, or current spatial code are changed.
- No backend calls are made.
- Prototype persistence is limited to optional browser localStorage and is not authoritative.
- Route planning, warehouse capacity optimization, multi-select, and printable labels are represented visually only where needed to match the supplied card; they are not production algorithms in this approval build.

## Acceptance criteria

1. `npm install && npm run dev` starts the prototype on localhost.
2. The initial 2D canvas shows an empty warehouse box on the engineering grid.
3. Users can create the full hierarchy, with invalid parent additions blocked.
4. Added nodes can be selected, moved, resized, renamed, locked, duplicated, and deleted.
5. Grid snapping, labels, dimensions, hierarchy tree, undo/redo, zoom, and fit work.
6. Switching between 2D and 3D preserves geometry and selection.
7. `Load sample` produces a layout visually comparable to the supplied Building/Storage/Layout screenshots.
8. The card remains usable at common laptop widths and has no clipped primary controls.
9. Automated model/geometry tests and the production build pass.
10. Browser inspection confirms no runtime errors and visually verifies both 2D and 3D modes.
